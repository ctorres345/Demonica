# Coding guidelines

Short rules that keep Demonica easy to change a year from now. When a rule and the code disagree, fix one of them in the same commit.

## 1. Where code goes

| You are writing... | Put it in | Not in |
| --- | --- | --- |
| A fusion rule, a recipe search, anything about the game's math | `packages/fusion_core` | a widget or provider |
| Loading, caching, saving, filtering for the UI | a provider or notifier (`lib/app/providers.dart` or the feature's `*_store.dart`) | a widget's `build` |
| A widget used by two or more screens | `lib/design_system/` | copied into each screen |
| A widget used by one screen | that screen's file, private (`_Name`) | design_system |
| A color, gap, radius or font | `tokens.dart` / `theme.dart` | a screen |

The engine never imports Flutter. If you need `Color` or `BuildContext` in `fusion_core`, the code is in the wrong place.

## 2. State (Riverpod)

- Watch the smallest thing you need. Use `ref.watch(provider.select(...))` or a narrow provider such as `fusionSettingsProvider`. Watching all of `settingsProvider` makes a screen rebuild when the palette changes.
- `ref.watch` in `build`, `ref.read` in callbacks (`onTap`, `onPressed`).
- Heavy work (anything that loops over all demons or all recipes) lives in a provider or in `GameData`, so it runs once and is cached. Never inside `itemBuilder`.
- Lists returned by `Smt4Rules.reverseRecipes` and `forwardRecipes` are cached and read-only. Copy (`[...list]`) before `sort` or `removeWhere`.
- A notifier that saves to the device: update `state` first, then save. Storage keys carry a version (`demonica.saved.v1`).

## 3. UI

- Colors from `context.dc` / `context.ec`, text styles from `context.tt`, gaps from `Space`, corners from `Radii`. No `Color(0xFF...)` in screens.
- Long lists: `ListView.builder`, with `itemExtent` when every row has the same height.
- Tap targets at least 48dp. Icon-only buttons get a `tooltip` (it is also the screen-reader label).
- Never color alone: an element dot sits next to its name, a resist cell has WK/RS/NU text.
- Copy is plain and short. Say what happens: "Turn off demons you have not unlocked yet", not "Configure availability".

## 4. Dart style

- Formatter at 100 columns (set in `analysis_options.yaml`). Run `dart format lib test tool packages/fusion_core`.
- `flutter analyze` and `dart analyze` must show **No issues found**. Rules are in the two `analysis_options.yaml` files: strict casts, `prefer_final_locals`, relative imports inside `lib/`, ordered imports, `unawaited_futures`.
- Do not silence a lint with `// ignore:` unless the comment next to it says why.
- Names say what the thing is in game terms: `reverseRecipes`, `freeSkillSlots`, `learnerCounts`. Avoid `data2`, `helper`, `manager`.
- Comments explain *why* or a game rule, in plain words. Doc comments (`///`) on every public class and on any function whose name is not the whole story.
- Prefer records and switch expressions over small one-use classes and `if` chains, like the existing code.

## 5. Tests

| Change | Test it with |
| --- | --- |
| Fusion rules or data import | `packages/fusion_core/test` (rule tests and the golden file), then the benchmark |
| A provider or notifier | a `ProviderContainer` test in `test/` (see `app_smoke_test.dart`, `saved_test.dart`) |
| A screen's behaviour | a widget test: pump the screen, tap, expect text |
| Palette colors | `test/design_tokens_test.dart` runs on its own |
| A bug fix | first a test that fails without the fix |

Never skip or delete a failing test to get green. Fix the code, or fix the test and say why in the commit.

## 6. Dependencies

- Add a package only when writing it yourself would take more than a day or needs platform code. Say why in the commit message.
- Keep versions current every few months: `flutter pub outdated`, upgrade, run `tool/check.sh`.
- The engine has zero runtime dependencies. Keep it that way.

## 7. Game data

- `assets/data/smt4/` is generated by `tool/import_smt4.dart`. Never edit it by hand; change the importer and re-run it.
- The upstream commit is pinned in the importer. Moving it is its own commit, with the golden tests passing.
- Atlus owns the names. Ship names and numbers only, no game art, and keep the "unofficial fan tool" line in Settings and on the welcome screen.
